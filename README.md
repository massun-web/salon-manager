# Salon Manager

2026-10-11の総点検結果、修正内容、未確認項目、公開前の課題は [品質点検レポート](docs/quality-review.md) を参照してください。

ポートフォリオ用のサロン予約管理Webアプリです。
Next.js（App Router）・TypeScript・ESLint を使用しています。
Supabase には接続せず、サンプルデータで予約管理を操作できます。

## 画面と操作

- `/`: ダッシュボード、今日の予約一覧、来店状況、スタッフ別予約数
- `/reservations`: 全予約一覧、顧客名・電話番号・メニュー・スタッフでの検索、日付・ステータス絞り込み
- `/trash`: 最近削除した予約、削除日時、完全削除までの残り時間、復元、完全削除
- `/customers`: 顧客一覧、名前・電話番号による検索、新規登録・編集・削除
- `/customers/[id]`: 顧客詳細、名前・電話番号・メモ・登録日、予約履歴・来店履歴
- 新規登録・編集: 顧客名、電話番号、予約日、時間、メニュー、担当スタッフ、ステータスを入力
- ステータス: 予約確定・来店済み・キャンセル
- 削除: 確認ダイアログからゴミ箱に移動。削除日時から72時間以内は元の内容で復元可能
- 完全削除: ゴミ箱の確認ダイアログから削除。起動時・ページ移動時・画面表示中・タブへ戻ったときにも期限切れを自動削除
- PC は表形式、スマートフォンはカード形式で表示

初回表示では、端末の今日の日付を基準に8件のサンプル予約を生成します。
操作結果は `localStorage` に保存し、ページ間で共有します。サーバー保存・他の端末との同期は行いません。
既存の保存キー・配列形式を維持し、削除済みの予約だけに `deletedAt`（ISO形式の削除日時）を追加します。旧データは変更せず読み込めます。
保存に失敗した場合は変更を適用せず、読み込めないデータは上書きしません。
アプリを閉じている間は処理が動かないため、72時間を超えたデータは次回起動時に削除します。期限判定には端末の時計を使用します。
復元先に同じ開始日時・担当スタッフの有効な予約がある場合、競合を知らせてゴミ箱に残します。
全ページの「デモデータをリセット」から、確認後に予約・顧客・ゴミ箱・メモを初期サンプルへ戻せます。キャンセル時は保存データを変更しません。公開準備の確認結果は [公開前チェック](docs/demo-publication.md) を参照してください。

電話番号と必須項目を検証し、同じ開始日時・担当スタッフでの重複予約を防止します。
施術時間による重複判定、営業時間、認証は今後の実装対象です。

## 顧客データと互換性

顧客情報は別の `salon-manager-customers-v1` キーに保存します。顧客操作で予約の保存データを書き換えたり、予約を削除したりしません。
初回および予約変更時に、既存予約（ゴミ箱内も含む）の電話番号を正規化して顧客を関連付けます。
ハイフン・空白・全角数字と、日本の `+81` 表記を正規化して同じ電話番号の重複を防ぎます。
関連付けた予約IDと変更前の電話番号を顧客側に保存するため、顧客の名前・電話番号を編集しても予約履歴を保持します。予約側には当時の情報がそのまま残ります。
電話番号は識別の手がかりであり、複数人で同じ番号を共有する場合は同一顧客として扱います。
予約の電話番号を後から編集した場合も、すでに関連付いた予約IDは元の顧客に保持します。

来店履歴は「来店済み」の予約（予約のゴミ箱内を除く）です。すべての予約履歴にはゴミ箱内の記録も区別して表示します。
予約の完全削除または72時間の期限切れ後は、その予約は履歴からも消えます。顧客を削除する操作では消えません。
既存予約から作成した顧客の登録日は、このアプリで顧客情報として取り込んだ日です。

顧客削除は確認画面を経て一覧から非表示にし、関連付けと削除済み記録を保存します。既存予約からの自動再登録を防ぎます。
削除した顧客と同じ電話番号で新規登録すると、同じ顧客ID・履歴の関連付けを引き継ぎます。
保存に失敗した場合は変更を適用せず、壊れた顧客データも上書きしません。顧客データが読み込めなくても、予約管理は独立して利用できます。
架空のサンプルデータで確認してください。Supabase接続や他の端末との同期は実装していません。

## 開発環境

Node.js 20.9 以上と npm が必要です。
このフォルダをプロジェクトルートとして使用します。

## 起動

```powershell
npm.cmd install
npm.cmd run dev
```

ブラウザで http://localhost:3000 を開いてください。
PowerShell の実行ポリシーの影響を避けるため `npm.cmd` を使用しています。
他のシェルでは `npm` も利用できます。

## 確認コマンド

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
npm.cmd start
```

`start` はビルド後の本番用サーバーを起動します。

ブラウザ操作の確認用に `scripts/verify-ui.mjs` を用意しています。
本番サーバーをポート3100で起動し、ヘッドレスChromeを `--enable-automation --remote-debugging-port=9223 --user-data-dir=<このプロジェクトの絶対パス>/.browser-test` で起動した状態で `node scripts/verify-ui.mjs` を実行します。
ブラウザの起動引数を確認し、プロジェクト内の独立した `.browser-test` プロファイル以外ではテストを実行しません。利用者のブラウザで実行しないでください。
予約・顧客の登録・編集・削除、入力検証、検索・日付・ステータス絞り込み、ゴミ箱、履歴、保存、既存データ保護、モバイル表示を確認します。
テストは確認用ブラウザの保存データを初期化し、終了時にそのブラウザを閉じます。
確認用プロファイルとスクリーンショットは `.browser-test/` に保存し、GitとLintの対象から除外します。

## ファイル構成

- `app/layout.tsx`: 共通レイアウトとメタデータ
- `app/page.tsx`: ダッシュボード
- `app/reservations/page.tsx`: 予約管理ページ
- `app/trash/page.tsx`: 最近削除した予約ページ
- `app/customers/`: 顧客一覧・詳細・データ保存・予約との関連付け
- `app/components/sidebar.tsx`: 全ページで共有するサイドバー
- `app/salon-manager.tsx`: 予約データの共有、画面、フォーム、ブラウザ保存
- `app/globals.css`: 管理画面のレスポンシブスタイル
- `next.config.ts`: Next.js 設定
- `tsconfig.json`: TypeScript 設定
- `eslint.config.mjs`: ESLint 設定

依存パッケージの初回インストールには npm レジストリへの接続が必要です。
インストールに成功すると `package-lock.json` が生成されます。
