# Salon Manager 品質点検（2026-10-11）

対象：Next.js 16.3.8 / React 19.3.0、予約・ゴミ箱・顧客管理、localStorage保存。
利用者の既存ブラウザデータは読み取り・初期化・消去していません。ブラウザテストは別プロファイル `.browser-test` と確認用ポート3100を使用しました。
Supabase接続、commit、push、依存パッケージの強制修正は実施していません。

## 調査結果と修正

| 重大度 | 問題 | 対応 |
| --- | --- | --- |
| 高 | 別タブの古い状態を保存すると最新の配列を上書きできる | 保存時に読み込み時点の文字列を照合。変更検出時は書き込みを拒否し、storageイベントで別タブの変更を反映 |
| 中 | 編集中に別タブで変更・削除された対象を上書きできる | 予約・顧客の編集元を確認し、対象が変更されていたら入力を保持して保存を拒否。削除確認中の変更にも対応 |
| 中 | 保存失敗でも予約フォーム・削除確認が閉じる | 成功した場合のみ閉じる。失敗は画面内で表示し、入力と元データを保持 |
| 中 | 重複予約ID、重複電話番号・履歴の所有者を検出しない | 予約IDと顧客IDの一意性、顧客間の電話番号・予約ID所有者を検証。不正データは修復・上書きせず操作停止 |
| 中 | 予約の検証・検索で顧客側と電話番号の扱いが異なる | 電話番号正規化を共有し、全角・空白・ハイフン・+81表記を処理。名前の長さも保存側で検証 |
| 中 | 一部の補助文・表見出しのコントラストが不足 | 文字色を調整。代表的な9種類の表示要素で4.5:1以上をブラウザ検証 |
| 低 | キーボードでメイン内容に移動しづらい、モバイルで表見出しがアクセシビリティツリーから消える | スキップリンクとフォーカス先を追加。表の列見出しにscopeを指定し、モバイルでは視覚的にのみ非表示 |
| 低 | 不正データの読み込み停止が読み込み中として見える | 操作停止の状態を表示し、既存データ保護を案内 |
| 低 | プロジェクト外のlockfileによるルート推定の警告 | Next.jsのビルド・ファイル追跡のルートをプロジェクトに指定 |
| 低 | 基本的なHTTPヘッダーが未設定 | nosniff、フレーム埋め込み禁止、Referrer-Policy、不要なカメラ・マイク・位置情報の制限を追加 |

既存の保存キー・配列形式・予約ID・顧客ID・削除日時を維持しています。予約編集と顧客編集では未知の追加プロパティも保持します。
競合データは自動マージ・削除・初期化しません。必要な場合は元データを退避したうえで、確認を伴う修復を別途実施してください。
localStorageへの読み取りと書き込みはトランザクションではないため、極めて近接した同時書き込みまで保証するものではありません。実運用にはサーバー側の排他制御が必要です。

## 依存関係

`eslint-config-next@16.3.8 → @next/eslint-plugin-next@16.3.8 → fast-glob@3.3.1 → micromatch@4.0.8 → braces@3.0.3` を確認しました。
braces 3.0.3にはHighのCVE-2026-93687があり、2026-10-11時点の[GitHub Advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)では修正版なしです。
確認した依存経路は開発用のLint依存です。利用者の入力をglobとして処理する機能は実装していませんが、これを理由に脆弱性が解消したとは判断していません。
`npm audit fix --force`、未検証のoverride、非公式パッチは適用していません。依存パッケージとlockfileも変更していません。

Next.js公式は、2026-10-14に上流依存のCritical 2件・High 1件に対する更新を予定しています。[公式告知](https://nextjs.org/blog/upcoming-nextjs-security-update-october-2026)
影響バージョンと詳細は更新時の公開予定です。このプロジェクトがそれらの影響を受けるかは現時点で未確認です。公開前に告知・修正版を確認し、互換性を維持して更新・再検証してください。

## 公開前に必要な作業

### ポートフォリオ用デモ

1. 通信可能な環境で `npm.cmd audit` を再実行し、全依存の現時点の脆弱性を評価する。10月14日のNext.js更新も確認する。
2. HTTPS環境で起動し、画面・HTTPヘッダー・ブラウザ保存を再確認する。現在の設定ではiframe埋め込みは拒否されるため、埋め込み公開が必要なら方針を決める。
3. 実データを配置せず、公開デモであること・端末内保存であることを明示する。別の実運用サイトと同一オリジンに配置しない。
4. 実機・主要ブラウザ・スクリーンリーダーで確認する。全要素のアクセシビリティ適合を認証した状態ではない。

### 実データを扱う業務アプリ

- 現状は認証・スタッフ別権限・サーバー保存・監査ログ・バックアップがない。共有端末のlocalStorageには氏名・電話番号・メモが平文で残る。実データの運用には使用しない。
- データ保持・匿名化・完全消去の方針を決める。顧客削除は論理削除で、個人情報自体の消去ではない。予約の完全削除・72時間失効で来店履歴も消えるという現在の仕様も再検討する。
- メニュー別の施術時間、開始／終了時刻、営業時間、予約可能なスタッフ、店舗のタイムゾーンを定義する。現在は開始日時の一致だけを防止し、時間帯全体の重複は検出しない。
- 顧客識別に電話番号を使う制限（家族での番号共有・番号の再割当て）を解消する。予約の顧客付替えは誤紐付け防止のため確認付きの別機能として設計する。
- サーバー側で入力検証とトランザクション・排他制御を実装する。端末時計に依存する72時間判定もサーバー時刻へ移す。
- CSP、ログ・外部サービスへの個人情報の混入防止、エクスポート・復旧、データ量に応じた性能検証を行う。

施術時間の導入、保持期間・顧客削除仕様の変更、サーバー移行は業務ルールと保存構造に影響するため、今回の点検では実施していません。
