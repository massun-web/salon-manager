# デモ公開準備（2026-10-12）

依存関係の再確認結果と公開判断は [依存関係セキュリティ確認](dependency-security.md) に記録。現時点では公開保留を推奨。

全ページ共通の「ポートフォリオ用デモ」案内と、ブラウザ保存・架空データ・実際の個人情報を入力しない旨の注意書きを追加。
「デモデータをリセット」は確認後のみ実行する。予約、顧客、メモ、ゴミ箱、削除済み顧客、履歴の関連付けを初期化し、今日を基準に8件の予約と8人の顧客を作成する。
予約日時・顧客登録日はリセット時点を基準とする。その他のlocalStorageキーには触れない。キャンセル、通常起動、更新ではこのリセット処理を実行しない。

確認時に2つの保存キーを読み取り、実行時に変更を検知したら拒否する。2番目の保存が失敗した場合は1番目を戻す。復旧も失敗した場合は再読み込みを案内する。localStorageには複数キー・複数タブを完全に排他制御するトランザクションがないため、同時書き込みの完全保証はない。

## 公開設定

- 必須の環境変数、APIキー、Supabase設定はない。API・サーバー保存・外部への顧客送信はない。
- Node.js 20.9以上。プロジェクトルートで `npm ci`、`npm run build`。本番起動は `npm start`。PowerShellでは `npm.cmd` を使用。
- Next.js対応のホスティングでHTTPSを使用する。静的HTMLエクスポート用の設定は行っていない。
- ソースと設定の機密情報候補を検索し、APIキー・パスワード・秘密鍵は検出なし。サンプルは架空の人物として作成したもの。電話番号が現実に未使用かどうかは保証できない。
- `.env*`、ブラウザテスト用プロファイル、ビルド成果物、npmキャッシュは除外設定済み。公開ファイルへこれらを含めない。
- 認証・暗号化・バックアップはなく、実際の顧客情報を扱う用途には使わない。同じブラウザの同じ公開先で保存データを共有し、他の端末とは共有しない。

## 残る依存関係の確認

`npm audit --json --cache .npm-cache --fetch-retries=0 --fetch-timeout=10000` はレジストリへの通信失敗により最新件数を取得できなかった。脆弱性0件とは判断できない。依存バージョンの変更、`npm audit fix --force` は実施していない。

インストール済みの依存経路：eslint-config-next 16.3.8 → @next/eslint-plugin-next 16.3.8 → fast-glob 3.3.1 → micromatch 4.0.8 → braces 3.0.3。
[bracesのHigh脆弱性 GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) は3.0.3以下が対象で、確認時点では修正版なし。上記は開発用Lint依存で、予約入力からこのパターン処理を呼ぶ経路はない。開発・CIの信頼できないglob入力には影響が残る。

[Next.js公式ブログ](https://nextjs.org/blog) は10月14日に上流依存のCritical 2件・High 1件への更新を予定している。公開前に正式アドバイザリの対象バージョンと修正版を確認し、必要な更新後にaudit・Lint・型チェック・build・操作テストを再実行する。
